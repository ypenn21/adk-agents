# Spec: Automated PR Reviewer, Quality Gate Agent & CI/CD Pipeline

**Status:** `Approved`

---

## What this does

Software pull requests and repository changes risk introducing critical security vulnerabilities, sensitive data/PII leaks, exposed API credentials, and architectural flaws into production. This system provides an automated, multi-agent CI/CD pipeline featuring a PR Reviewer Agent and a Quality Gate Decision Agent powered by Google Antigravity and Vertex AI (Gemini), coupled with Google Cloud DLP scanning. The agents analyze pull request diffs, detect sensitive data, publish inline and consolidated reviews on GitHub, generate auditable artifacts, and enforce a strict zero-tolerance gate before production builds.

---

## Input

The pipeline consumes inputs from GitHub Actions runner environment variables, generated file system reports, and the GitHub REST API:

### 1. Environment Variables
- `GITHUB_REPOSITORY` / `REPOSITORY`: GitHub repository name in `owner/repo` format (string). Validated against regex `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`.
- `PULL_REQUEST_NUMBER` / `PR_NUMBER`: Pull request number (numeric string or integer). If absent or `None`, indicates a non-PR push event.
- `GH_TOKEN` / `GITHUB_TOKEN` / `GITHUB_PERSONAL_ACCESS_TOKEN`: GitHub authentication token (Bearer token string).
- `GOOGLE_CLOUD_PROJECT` / `GCP_PROJECT`: GCP Project ID (string, defaults to `local-project` if unset).
- `GOOGLE_CLOUD_LOCATION`: GCP Region (string, defaults to `us-central1`).
- `LLM_Model` / `LLM_MODEL`: Target Gemini model identifier (string, defaults to `gemini-3.7-flash`).

### 2. File System Artifacts
- `reports/pii-scan.txt`: Text output from Cloud DLP scan and regex inspection containing detected PII/secret findings or clean confirmation string (`✅ No sensitive data or PII detected by Cloud DLP.`).
- `reports/pii-scan.json`: Structured JSON array of DLP inspection findings.
- `reports/pr-review.txt`: Text summary of code review findings generated by the PR Reviewer Agent.
- `reports/pr-review.json`: Machine-readable JSON artifact of `PRReviewReport`.
- `reports/decision.txt`: Text summary of the release gate decision starting with `GATE_PASSED` or `GATE_FAILED`.
- `reports/gate-decision.json`: Machine-readable JSON artifact of `QualityGateDecision`.

### 3. GitHub REST API Data
- Pull request diff hunks fetched from `GET /repos/{owner}/{repo}/pulls/{pr_number}/files`.
- Existing pull request review comments fetched from `GET /repos/{owner}/{repo}/pulls/{pr_number}/comments`.

## The two halves

The system interfaces are structured between agent core types, execution coroutines, and GitHub/filesystem helper utilities in `.github/scripts/`:

```python
from __future__ import annotations
from enum import Enum
from typing import Optional, Any, Dict, List, Tuple
from pydantic import BaseModel, Field, model_validator

# =====================================================================
# Half 1: PR Reviewer Agent Types & Contracts (.github/scripts/pr_reviewer_agent.py)
# =====================================================================

class PRFindingSeverity(str, Enum):
    BLOCKER = "BLOCKER"
    WARNING = "WARNING"
    SUGGESTION = "SUGGESTION"
    INFO = "INFO"

# Backward compatibility alias
ReviewSeverity = PRFindingSeverity

class ReviewStatus(str, Enum):
    APPROVE = "APPROVE"
    REQUEST_CHANGES = "REQUEST_CHANGES"
    COMMENT = "COMMENT"

class InlineFinding(BaseModel):
    file_path: str
    line_number: Optional[int] = None
    severity: PRFindingSeverity = PRFindingSeverity.INFO
    title: str
    details: str
    suggestion: str = ""
    pii_leak: bool = False

class PRReviewReport(BaseModel):
    overall_status: ReviewStatus
    summary: str
    findings: List[InlineFinding] = Field(default_factory=list)

    @model_validator(mode="after")
    def enforce_blocker_status(self) -> "PRReviewReport":
        has_blocker = any(
            f.severity == PRFindingSeverity.BLOCKER or f.pii_leak
            for f in self.findings
        )
        if has_blocker and self.overall_status != ReviewStatus.REQUEST_CHANGES:
            self.overall_status = ReviewStatus.REQUEST_CHANGES
        return self

POSITIVE_APPROVAL_TEMPLATE: str = (
    "## ✅ Automated PR Review: APPROVED\n\n"
    "Great job! No code defects, architectural issues, or Cloud DLP security findings "
    "were identified in this pull request.\n\n"
    "- **Security SAST / Secrets:** Clean\n"
    "- **PII / DLP Scan:** Passed (0 findings)\n"
    "- **Code Quality:** Verified\n"
)

# =====================================================================
# Half 2: Quality Gate Decision Agent Types (.github/scripts/quality_gate_agent.py)
# =====================================================================

class SeverityLevel(str, Enum):
    CRITICAL = "CRITICAL"
    HIGH = "HIGH"
    MEDIUM = "MEDIUM"
    LOW = "LOW"

class ViolationCategory(str, Enum):
    PII_LEAK = "PII_LEAK"
    CREDENTIAL_LEAK = "CREDENTIAL_LEAK"
    SECURITY_VULNERABILITY = "SECURITY_VULNERABILITY"
    ARCHITECTURAL_DEFECT = "ARCHITECTURAL_DEFECT"

class FailureDetail(BaseModel):
    category: ViolationCategory
    component: str
    severity: SeverityLevel
    reason: str
    remediation: str

class QualityGateDecision(BaseModel):
    passed: bool
    summary: str
    failures: List[FailureDetail] = Field(default_factory=list)

    @model_validator(mode="after")
    def validate_failures_consistency(self) -> "QualityGateDecision":
        if self.passed and len(self.failures) > 0:
            raise ValueError("QualityGateDecision cannot be passed=True with non-empty failures")
        if not self.passed and len(self.failures) == 0:
            raise ValueError("QualityGateDecision cannot be passed=False with empty failures")
        return self

# =====================================================================
# Core Agent Execution & Helper Function Signatures (.github/scripts/helper.py)
# =====================================================================

def sanitize_and_validate_repo(repo: str) -> str: ...

def is_duplicate_comment(
    new_path: str,
    new_line: Optional[int],
    new_title: str,
    existing_comments: List[Dict[str, Any]],
) -> bool: ...

def validate_and_sanitize_findings(
    findings: List[InlineFinding],
    modified_files_diff: Optional[Dict[str, List[int]]] = None,
    existing_comments: Optional[List[Dict[str, Any]]] = None,
) -> Tuple[List[Dict[str, Any]], List[InlineFinding], int]: ...

def format_pr_review_text(report: PRReviewReport) -> str: ...

def format_text_decision(decision: QualityGateDecision) -> str: ...

def write_pr_reports(report: PRReviewReport, output_dir: str = "reports") -> None: ...

def write_gate_reports(decision: QualityGateDecision, output_dir: str = "reports") -> None: ...

def parse_agent_structured_output(raw_output: Any, target_cls: Any) -> Any: ...

async def run_pr_review(
    pr_number: Optional[str] = None,
    repo: Optional[str] = None,
    token: Optional[str] = None,
    pii_report_path: str = "reports/pii-scan.txt",
    project_id: Optional[str] = None,
    location: Optional[str] = None,
    model: Optional[str] = None,
    modified_files_diff: Optional[Dict[str, List[int]]] = None,
) -> Optional[PRReviewReport]: ...

async def evaluate_quality_gate(
    pii_report_path: str = "reports/pii-scan.txt",
    pr_review_path: str = "reports/pr-review.txt",
    project_id: Optional[str] = None,
    location: Optional[str] = None,
    pr_number: Optional[str] = None,
    model: Optional[str] = None,
) -> QualityGateDecision: ...
```

## Rules

### 1. Import Resilience & Dependency Isolation
- `google.antigravity` must be conditionally imported with try/except fallbacks in all scripts (`pr_reviewer_agent.py`, `quality_gate_agent.py`, `helper.py`) setting `Agent = None`, `LocalAgentConfig = None`, `types = None` when unavailable.
- Unit and contract tests must be executable in standard Python test environments without requiring proprietary SDK packages or active cloud credentials.
- Test suites running asynchronous coroutines must be configured via `pytest-asyncio` or `anyio` without requiring manual event loops.

### 2. PR Reviewer Behavior & Invariants
- When `pr_number` is `None` or empty (such as on push events to branches), `run_pr_review` must exit immediately returning `None` without performing network requests.
- For pull requests, findings must be mapped against diff hunk coordinates (`modified_files_diff`). Line numbers present in the diff hunk are converted to GitHub inline review comments; out-of-hunk findings or findings without line numbers are consolidated into the top-level review body.
- If any finding has `severity == PRFindingSeverity.BLOCKER` or `pii_leak == True`, `PRReviewReport.overall_status` is strictly enforced as `ReviewStatus.REQUEST_CHANGES`.
- Clean PRs (zero findings) must submit a review with event `COMMENT` or `APPROVE` containing `POSITIVE_APPROVAL_TEMPLATE` and an empty inline comments list.
- Prior to submitting to GitHub, report artifacts must be persisted to `reports/pr-review.json` and `reports/pr-review.txt`.

### 3. Anti-Spam Deduplication & Anti-Flake Network Resilience
- The PR Reviewer must fetch prior review comments via `GET /repos/{owner}/{repo}/pulls/{number}/comments`.
- `is_duplicate_comment` must inspect existing comments by matching `path`, `line` (or `original_line`), and checking if the finding title exists case-insensitively in the comment body. Existing duplicate inline comments are skipped to prevent comment spam across CI re-runs.
- Network exceptions during review submission or comment retrieval must be caught, logged as warnings (`[Warning] Failed to post PR review to GitHub`), and must not cause the agent process to raise uncaught exceptions or exit with non-zero error codes.
- If GitHub API rejects an inline review with HTTP 422 (e.g. invalid diff coordinate or self-review submission), the agent must automatically retry submission by posting a consolidated top-level review without inline comments, or fall back to posting an issue comment via `POST /repos/{owner}/{repo}/issues/{number}/comments`.

### 4. Quality Gate Evaluation & Fail-Closed Release Criteria
- The Quality Gate Decision Agent evaluates both `reports/pii-scan.txt` and `reports/pr-review.txt`.
- **Fail-Closed DLP Rule:** If `reports/pii-scan.txt` is missing, unreadable, or 0 bytes (empty), the Quality Gate MUST fail closed with `passed = False`, `SeverityLevel.CRITICAL`, and `ViolationCategory.SECURITY_VULNERABILITY` referencing the `Cloud DLP` component.
- **Active PR Rule:** If `pr_number` is set (active PR event) and `reports/pr-review.txt` is missing or unreadable, the gate MUST fail with `passed = False` and `SeverityLevel.HIGH` or `CRITICAL` referencing `PR Reviewer`.
- **Non-PR / Push Event Rule:** If `pr_number` is `None` (push event to `main`) and `reports/pr-review.txt` is missing, the gate MUST PASS provided that Cloud DLP reports zero PII findings.
- **Zero-Tolerance Invariant:** A `QualityGateDecision` with `passed = True` MUST have `failures = []`. A decision with `passed = False` MUST have `len(failures) > 0`. Any mismatch must raise a `ValidationError`.
- `evaluate_quality_gate` must write `reports/gate-decision.json` and `reports/decision.txt` (prefixed with `GATE_PASSED\n\n` or `GATE_FAILED\n\n`), and ensure the telemetry directory `reports/telemetry/quality_gate_agent/` exists.
- The CLI invocation must exit with status code 0 so that GitHub Actions workflow execution can proceed to archive telemetry artifacts before enforcement.

### 5. Workflow Enforcement & CI/CD Gating
- `.github/workflows/source-code-pii-review.yml` configures Python 3.11 with `actions/setup-python@v5` and installs `google-antigravity` and `pydantic`. Legacy `curl | bash` CLI installer scripts are eliminated.
- The workflow executes `python .github/scripts/pr_reviewer_agent.py` and `python .github/scripts/quality_gate_agent.py`.
- The `Enforce Quality Gate` step parses `reports/gate-decision.json` and halts deployment (`exit 1`) if `passed` is not `True`.
- Telemetry logs and all audit artifacts inside `reports/` are uploaded to Google Cloud Storage via `google-github-actions/upload-cloud-storage@v2`.
- The downstream `build` containerization job executes only on `push` events to `refs/heads/main` after `scan-and-evaluate` succeeds.

## Out of scope

- Direct automated merging of pull requests or git commit creation.
- Live modification of Cloud DLP inspection templates in GCP at runtime.
- External Slack or Microsoft Teams webhook dispatchers.
- Relational database schema migrations within the CI quality gate agent.
