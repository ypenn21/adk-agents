# Spec: Automated PR Reviewer & Quality Gate CI/CD Pipeline

**Status:** `Approved`

---

## What this does

Software pull requests risk introducing security vulnerabilities, sensitive data/PII leaks, credential exposures, and architectural defects into production. This pipeline runs an automated PR Reviewer Agent and Quality Gate Decision Agent in GitHub Actions using Vertex AI and Cloud DLP to inspect PR diffs, detect sensitive data, publish inline review comments on GitHub, and enforce a strict zero-tolerance gate before deployment.

---

## Input

The pipeline operates on inputs supplied via GitHub Actions environment variables, files from prior job steps, and the GitHub REST API:

### Environment Variables & Parameters
- `GITHUB_REPOSITORY` / `REPOSITORY`: GitHub repository in format `owner/repo` (string). Must match regex `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`.
- `PULL_REQUEST_NUMBER` / `PR_NUMBER`: Pull request number (positive integer or numeric string).
- `GH_TOKEN` / `GITHUB_TOKEN` / `GITHUB_PERSONAL_ACCESS_TOKEN`: GitHub authentication token (string).
- `GOOGLE_CLOUD_PROJECT` / `GCP_PROJECT`: GCP Project ID (string, defaults to `local-project` if absent).
- `GOOGLE_CLOUD_LOCATION`: GCP Location (string, defaults to `us-central1`).
- `LLM_Model` / `LLM_MODEL`: Model name (string, defaults to `gemini-3.7-flash`).

### File System Inputs
- `reports/pii-scan.txt`: Text output from Cloud DLP scan containing detected PII findings or confirmation message.
- `reports/pii-scan.json`: JSON array of DLP scan findings.
- `reports/review.txt`: Text summary of the PR code review generated by the PR Reviewer Agent.
- `reports/pr-review.json`: JSON payload of the structured `PRReviewReport`.

## The two halves

The system is partitioned into two core agent workflows and a shared helper layer in `.github/scripts/`:

```python
from __future__ import annotations
from enum import Enum
from typing import Optional, Any
from pydantic import BaseModel, Field, model_validator

# ==========================================
# 1. PR Reviewer Types (.github/scripts/pr_reviewer_agent.py)
# ==========================================

class PRFindingSeverity(str, Enum):
    BLOCKER = "BLOCKER"
    WARNING = "WARNING"
    SUGGESTION = "SUGGESTION"
    INFO = "INFO"

ReviewSeverity = PRFindingSeverity

class ReviewStatus(str, Enum):
    APPROVE = "APPROVE"
    REQUEST_CHANGES = "REQUEST_CHANGES"
    COMMENT = "COMMENT"

class InlineFinding(BaseModel):
    file_path: str
    line_number: Optional[int] = None
    severity: PRFindingSeverity = PRFindingSeverity.INFO
    title: str
    details: str
    suggestion: str = ""
    pii_leak: bool = False

class PRReviewReport(BaseModel):
    overall_status: ReviewStatus
    summary: str
    findings: list[InlineFinding] = Field(default_factory=list)

    @model_validator(mode="after")
    def enforce_blocker_status(self) -> "PRReviewReport":
        has_blocker = any(
            f.severity == PRFindingSeverity.BLOCKER or f.pii_leak
            for f in self.findings
        )
        if has_blocker and self.overall_status != ReviewStatus.REQUEST_CHANGES:
            self.overall_status = ReviewStatus.REQUEST_CHANGES
        return self

# ==========================================
# 2. Quality Gate Types (.github/scripts/quality_gate_agent.py)
# ==========================================

class SeverityLevel(str, Enum):
    CRITICAL = "CRITICAL"
    HIGH = "HIGH"
    MEDIUM = "MEDIUM"
    LOW = "LOW"

class ViolationCategory(str, Enum):
    PII_LEAK = "PII_LEAK"
    CREDENTIAL_LEAK = "CREDENTIAL_LEAK"
    SECURITY_VULNERABILITY = "SECURITY_VULNERABILITY"
    ARCHITECTURAL_DEFECT = "ARCHITECTURAL_DEFECT"

class FailureDetail(BaseModel):
    category: ViolationCategory
    component: str
    severity: SeverityLevel
    reason: str
    remediation: str

class QualityGateDecision(BaseModel):
    passed: bool
    summary: str
    failures: list[FailureDetail] = Field(default_factory=list)

    @model_validator(mode="after")
    def validate_failures_consistency(self) -> "QualityGateDecision":
        if self.passed and len(self.failures) > 0:
            raise ValueError("QualityGateDecision cannot be passed=True with non-empty failures")
        if not self.passed and len(self.failures) == 0:
            raise ValueError("QualityGateDecision cannot be passed=False with empty failures")
        return self

# ==========================================
# 3. Agent Execution Signatures
# ==========================================

async def run_pr_review(
    repo: Optional[str] = None,
    pr_number: Optional[str] = None,
    token: Optional[str] = None,
    project_id: Optional[str] = None,
    location: str = "us-central1",
    model: Optional[str] = None,
) -> PRReviewReport:
    """Executes PR review, parses diff, runs LLM agent, posts GitHub review, and writes reports."""
    ...

async def evaluate_quality_gate(
    pii_file: str = "reports/pii-scan.txt",
    pr_review_file: str = "reports/review.txt",
    project_id: Optional[str] = None,
    location: str = "us-central1",
    model: Optional[str] = None,
) -> QualityGateDecision:
    """Evaluates DLP findings and PR review outputs against release criteria and writes reports."""
    ...
```

## Rules

### 1. Configuration Resolution & Fallbacks
- Configuration is resolved with CLI arguments taking top priority, followed by primary environment variables, fallback environment variables, and sensible defaults (`local-project`, `us-central1`, `gemini-3.7-flash`).
- Empty or whitespace-only environment variables are treated as `None`.

### 2. PR Reviewer Behaviour & Enforcements
- The PR Reviewer fetches the PR diff and existing comments via GitHub REST API.
- `InlineFinding` line numbers and file paths must be validated against actual modified lines in the PR diff hunks before constructing GitHub inline comments. Findings outside diff hunks are omitted from inline comments but retained in the PR review summary.
- If any finding has `severity == PRFindingSeverity.BLOCKER` or `pii_leak == True`, `PRReviewReport.overall_status` is strictly enforced as `ReviewStatus.REQUEST_CHANGES`.
- When findings are empty and no DLP findings exist, the agent posts a clean approval using `POSITIVE_APPROVAL_TEMPLATE` with `ReviewStatus.APPROVE`.
- Reviews are submitted via `POST /repos/{owner}/{repo}/pulls/{number}/reviews`. If GitHub returns HTTP 422 (e.g. line outside hunk or outdated commit), the agent falls back to posting a top-level issue comment via `POST /repos/{owner}/{repo}/issues/{number}/comments`.

### 3. Quality Gate Evaluation & Release Criteria
- The Quality Gate Agent evaluates the aggregated `reports/pii-scan.txt` and `reports/review.txt`.
- **Zero-Tolerance Gate:** Any detected PII/credential leak or `BLOCKER`/`CRITICAL` security flaw results in `passed = False` with a populated list of `FailureDetail` records.
- Invariant: A `QualityGateDecision` with `passed = True` MUST have `failures = []`. A decision with `passed = False` MUST have `len(failures) > 0`. Any mismatch raises a `ValueError`.

### 4. Report Generation & Dual Serialization
- Agents must write both human-readable text reports and machine-readable JSON artifacts:
  - PR Review: `reports/review.txt` and `reports/pr-review.json`
  - Quality Gate: `reports/decision.txt` (containing `GATE_PASSED` or `GATE_FAILED`) and `reports/gate-decision.json`
- Directory `reports/` is created automatically if it does not exist.

### 5. Input Sanitization & Anti-Spam Deduplication
- `GITHUB_REPOSITORY` is validated against `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`. Invalid formats raise `ValueError`.
- To prevent spam across CI reruns, `is_duplicate_comment` compares new comment content against existing comments on the PR; matching comments are skipped.

## Out of scope

- Direct auto-merging or git commit authoring.
- Direct database writes or external notification services (Slack/Teams).
- Modifying Cloud DLP inspection templates dynamically at runtime.
